# ADVANCED · 网上仓位控制方法的回测（POS-02，2026-11-03）

**问题**：除了已测的"波动率目标 + 回撤节流 + 止损 + Kelly + 单票上限"，网上还有哪些经典仓位方法？在同一个 S2 信号上能不能打得过 VT15？

**数据/口径**：`data/cache2019`，ext 52 只 / base 30 只 ETF，2019-08-13~2026-11-02，单边 5bp；
信号、调仓（5 日）、delay=1、成本与 `position/engine.py` 的 S2 完全一致；基线逐位复现 18.84%/−33.58%/0.561。
**性质**：同一批数据上的再检验，不是样本外；只改仓位层。

## 1. 测了哪些方法

| 方法 | 规则 | 参数 |
|---|---|---|
| VT15（基准） | 敞口 = 15% / 60 日已实现波动，封顶 100% | 目标 15%，窗口 60 |
| EWMA 波动目标 | 用 EWMA 方差代替 60 日简单方差 | λ=0.97（半衰期约 23 日），目标 15% |
| CVaR 目标 | 敞口 = 目标 CVaR / 60 日 5% 历史 CVaR | 目标 2%/日；另测 1.5% |
| CPPI（基本） | floor=初始 80%，敞口=M×(NAV−floor)/NAV | M=3 |
| CPPI（峰值 floor） | floor=峰值×75%/85%/90%，敞口=M×cushion/NAV | M=3/5/8 |
| ERC 风险平价 | 126 日协方差，迭代让 5 只风险贡献相等；可加单票 cap | 126 日，cap 1 或 40% |
| 最大分散化 MDP | 最大化 (w·σ)/√(wᵀΣw) | 126 日，SLSQP |
| ERC / MDP + VT15 | 先按 ERC/MDP 分权重，再乘 VT15 敞口 | — |

实现：`position/advanced.py`；ERC/MDP 权重在 `position/engine.py: _scheme_weights`。
来源与公式见 `SOURCES.md`。

## 4. 结论

1. **VT15 仍是主力**：两池、三段、对同仓位对照都成立；本轮没有方法在 Sharpe 上稳定超过它。
2. **ERC + VT15 可以当"低回撤替换"**：ext 卡玛 1.01、回撤 -15.66%（VT15 0.99/-16.22%）；base 0.76 vs 0.72。
   但 Sharpe 差在 0 附近，属于"同风险收益、少一点回撤"，不是免费 alpha。
3. **加 cap40** 两池都略好（ext 1.06、base 0.78；CAGR 也略高），但差异仍在噪声内。若实盘要控单票集中，cap40 可作为护栏。
4. **EWMA / CVaR 不划算**：更复杂的风险估计没有带来更好的风险调整收益，且 CVaR 目标 2% 把仓位压到 62%，收益让渡更大。
5. **CPPI 不适合这个策略**：
   - 初始 floor 80% 的版本根本压不住峰值回撤（-33.58%，和满仓一样），因为 floor 不随净值上移；
   - 峰值 floor 版本（75%/85%/90%）把平均仓位压到 6%~54%，年化掉到 0~9%，卡玛 0.25~0.47；
   - CPPI 是"保本产品"工具，不是"高波动动量策略"的收益增强器；要保本就得接受低收益。
6. **ERC/MDP 单独用**（满仓）对结果影响很小：权重层不如总敞口层重要；MDP 换手 48 倍/年，成本更贵。
7. **ATR/HRP/GARCH 没测**：当前缓存没有 high/low，ATR 无法硬造；HRP 在 5 只上边际小；GARCH 需要 `arch` 包。见 `SOURCES.md`。

## 5. 建议

- 继续用 **VT15 + 单票 40% 上限**（`POLICY_v1.md`）作为基线 policy。
- 若想再降一点回撤，可把个券权重从"逆波动"换成 **ERC（126 日）**，但预期只改善 0.5~1pp 回撤，不要期待收益提升。
- **不要用 CPPI** 在这个策略上；它会在牛市把仓位压得太低。
- 下一步若要测 ATR/HRP/GARCH，先补 high/low 数据或装 `arch`，再写预登记。
